# 측정 정의와 규칙

> 효과 검증에서 쓰는 용어와 측정 규칙을 정한다. 검증 설계는 [validation/overview.md](overview.md)에 있다. 값은 모두 임시이며 M1에서 확정한다.

## 1. 용어

| 용어 | 정의 |
|---|---|
| T0 (스래싱 시작) | `tg-sampler` 기준, 시스템 PSI `full` 1초 구간 비율이 10% 이상인 상태가 처음 3초 연속된 시점 |
| T_detect | 데몬이 "스래싱 지속"으로 판단한 시각(판단 로그) |
| T_kill | 종료가 실행된 시각(`cgroup.kill` 쓰기 또는 커널 OOM killer 호출) |
| T_resolve (해소) | 시스템 PSI `full` 1초 구간 비율이 10% 미만인 상태가 10초 연속된 첫 시점. **`T0` 이후에 시작한 구간만** 쓴다(실행 초기에 압력이 낮았던 구간을 해소로 잡지 않기 위해). 데몬 꺼짐에서 부하가 자연 종료되거나 커널 OOM killer가 발동해도 같은 정의로 판단한다 |
| 해소 시간 | T_resolve − T0. 구성은 아래 1.1절 |
| 미해소 | T0 + 5분까지 T_resolve가 없음. 이후 실행을 종료하고 정리한다. dry-run의 미해소는 "5분 이상"으로만 표시한다 |
| 오탐 | T0가 나오지 않은 실행에서 데몬이 종료를 결정한 것(판단 로그의 첫 `judge kill`). 정상 버스트의 합격 기준이다 |
| 필수 프로세스 응답 | VM 밖에서 1초마다 필수 프로세스 E(카나리)에 TCP 요청, 새 연결 SSH(`ssh vm true`, 타임아웃 5초). 최대 무응답 시간과 성공률을 기록한다 |
| 기준 구간 | 실행 시작 후 E가 응답하는 15초. 이 구간이 끝나면 부하를 투입한다 |
| 종료된 대상 | 종료된 cgroup 이름과 역할(부하, E, 기타) |

T0의 10%는 실험에서 스래싱 시작을 넓게 잡는 **관찰 기준**이고, 데몬이 종료를 결정하는 임계(`full_pct`, 초기값 10%)와는 별개다. 데몬 임계는 이 실험으로 조정한다.

### 1.1 해소 시간의 구성

데몬 켜짐에서 해소 시간은 세 구간으로 나뉜다.

```text
T0 ──────► T_detect ──► T_kill ──────► T_resolve
 스래싱     데몬이       종료 실행      시스템 회복
 시작       결정                        확인
 (감지 지연)            (종료 후 회복 지연)
```

- 감지 지연: T0부터 T_detect까지. 첫 판단에 10초 윈도가 차야 해서 최소 10초 안팎이다.
- 종료 후 회복 지연: T_kill부터 T_resolve까지. 종료한 프로세스가 디스크 읽기를 기다리느라 SIGKILL 처리가 늦을 수 있고, 메모리가 풀려도 `full`이 10% 미만으로 10초 연속되어야 해소로 본다.
- 10초 연속 조건 때문에 종료 즉시 회복해도 해소 시간에는 최소 10초가 더해진다. dry-run과 켜짐이 같은 정의를 쓰므로 비교는 공정하다.

데몬 dry-run에서는 종료가 없으므로 해소 시간은 커널 OOM killer나 부하 자체의 종료로 풀린 시간이다. 5분 안에 풀리지 않으면 미해소다.

SSH 프로브는 연결 재사용(ControlMaster)을 쓰지 않는다. 재사용하면 sshd의 `fork`·로그인 경로를 건너뛰어 실제 접속 가능 여부를 반영하지 못하기 때문이다.

## 2. 시각과 수집

- 시각은 모두 VM 밖 수신기의 시계로 맞춘다. 샘플러는 자체 단조 시계도 함께 보내 전송 지연을 확인한다.
- 샘플러 `tg-sampler`는 250 ms 주기로 PSI·vmstat·meminfo를 읽어 UDP 텍스트 한 줄씩(일련번호 포함) VM 밖 수신기에 보낸다. 디스크 쓰기를 핵심 경로에서 빼고, 강제 리셋 때 기록이 유실되지 않게 하려는 것이다.
- PSI는 `avg10`이 짧은 stall을 놓치므로(M0 실측) 누적값 `total`의 차분으로 계산한다.

## 3. 측정 규칙

- 측정자는 반드시 대상 호스트 밖에 둔다(VM 밖 SSH 프로브, UDP 수집기).
- 시나리오·조건별 3회 이상 반복하고 중앙값과 범위를 보고한다.
- `T0` 이후 5분 안에 해소되지 않으면 "미해소"로 기록하고 정리한다. 부하를 시작한 지 10분 안에 `T0`가 나타나지 않으면 "스래싱 미발생"으로 기록하고 종료한다(임시).
- dry-run의 판단 로그는 첫 결정 시각만 `T_detect`로 쓴다. dry-run의 가상 종료도 시간당 상한을 소모하므로 첫 결정 이후의 `hourly_limit`, `no_candidate` 건너뜀은 해석하지 않는다.
- 정상 버스트의 크기와 `BURST_MEM`의 크기·유지 시간은 예비 실행(보정용)으로 맞춘다. 보정에 쓴 실행은 평가 실행과 구분해 기록한다.
- 수신기에서 일련번호가 건너뛴 구간은 무효로 기록하고, 무효 구간이 포함된 3초·10초 연속 조건은 판정하지 않는다. UDP는 전달을 보장하지 않기 때문이다. 현재 분석 스크립트는 일련번호를 읽지 않으므로 효과 검증 전에 추가한다.
- 원본 데이터는 `results/`에 커밋해 재검증할 수 있게 한다.
- 표본 부족 등 해석의 한계를 결과와 함께 적고, 실측과 추론을 구분한다.
- 임계값 보정에 쓴 실행과 평가에 쓴 실행을 구분한다.
