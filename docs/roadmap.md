# Thrash Guard 로드맵

> 개략적인 순서와 진행 상황만 적는다. 목적과 범위는 [plan.md](plan.md), 데몬 설계는 [design/overview.md](design/overview.md), 검증 방법은 [validation/overview.md](validation/overview.md), 실험 환경과 실측은 [lab/environment.md](lab/environment.md)에 있다.
> 최종 개정: 2026-11-13 (M4 효과 검증 구성 단순화: 부하 하나와 dry-run/켜짐 비교)

## 마일스톤

| 단계 | 내용 | 상태 |
|---|---|---|
| M0 | 기반: 저장소, 공용 모듈, 수집 경로, 실험용 VM | 완료 |
| M1 | 검증 도구와 최소 재현 | 미착수 |
| M3 | 데몬 MVP | 진행 중 |
| M4 | 효과 검증 | 미착수 |
| M5 | 개선 기능 | 후속 선택 |
| M6 | 공개 정리 | 미착수 |
| M7 | 후속 확장 | 후속 선택 |

M2(기준선 측정)는 삭제했다. 데몬 꺼짐 조건이 기준선 역할을 하고, 기존 도구와의 비교는 M7로 미뤘다.

```text
M0 (완료) ─┬─ M1 (검증 도구, 최소 재현) ──────────────┐
           │                                          ├─ M4 (효과 검증) ─ M6 (공개) ─ M5·M7 (후속)
           └─ M3 (데몬 MVP, M1과 병행) ───────────────┘
```

## M1. 검증 도구와 최소 재현

- `tg-load`: `RUNAWAY_GROWTH`(`anon`), `SPIKE_MEM`(`anon --rate-mib 0`), `BURST_MEM`·정상 버스트(`burst`), 필수 프로세스 카나리(`canary`). 정상 앱 W(`steady`)와 `FILE_THRASH`(`file-thrash`) 모드는 구현돼 있으나 M4에서 쓰지 않는다
- 단순한 실행 하네스 `lab/run.sh`: 스냅샷 복원, 데몬 꺼짐/켜짐, 부하 실행, 해소 또는 타임아웃, 결과 저장
- 부하 크기 예비 실행(`SPIKE_MEM`의 즉시 할당, `BURST_MEM`과 정상 버스트의 크기), 스래싱 중 샘플러 누락률 확인

완료 조건: 부하 3종이 데몬 dry-run에서 의도한 모양(폭주는 스래싱이 나고 정상 버스트는 나지 않음)으로 동작하고, 그렇지 않은 경우의 사유와 범위가 기록된다.

참고: 이전 계획의 M1 작업(`tg-load`의 `anon`·`file`·`pin`·`canary` 모드, `lab/run.sh`, 재현 판정과 측정 결과)이 저장소에 있다. 재현 판정 실험은 **참고용**이며 위 설계의 근거나 전제가 아니다. 기록은 [lab/environment.md](lab/environment.md) 5절.

## M3. 데몬 MVP

시스템 멈춤을 감지해 비보호 후보를 종료하는 최소 기능이다. 처음에는 판단만 기록하는 dry-run으로 오탐을 확인한다.

| ID | 작업 | 상태 |
|---|---|---|
| M3-1 | 설정 파서와 CLI | 완료 |
| M3-2 | 이벤트 루프: 시스템 PSI 트리거, 시그널 처리, 틱 처리, 루프 지연 측정 | 완료 |
| M3-3 | 후보 탐색 스레드, 유예·쿨다운·시간당 상한 | 완료 |
| M3-4 | 판단 함수 | 완료 (시스템 PSI 평균, 사용량·증가량 선택) |
| M3-5a | 로그 링버퍼와 기록 스레드 | 완료 |
| M3-5b | 종료 경로: `cgroup_kill` (`oom_kill`은 후속) | 완료 |
| M3-6 | 초기화 이후 무할당 검증 | 완료 (`test_noalloc`. 루프 `poll` 경로는 대상 밖) |
| M3-11 | 굳어진 livelock 대응: 판단 함수에 io 경로 추가 (`io_full_pct`, `io_mem_avail_pct`) | 완료 (단위 테스트, 기록 재생, VM 실제 종료 2/2가 io 경로로 종료. 임시값) |
| M3-10 | 시작 시 환경 점검(cgroup v2, memory 컨트롤러, `cgroup.kill`) | 완료 (실제 종료 모드는 실패 시 시작 거부) |
| M3-8 | systemd 서비스 파일 | 완료 (`packaging/`. 값은 임시이고 VM에서 서비스로 기동해 확인 필요) |
| M3-9 | 필수 프로세스 보호 drop-in, 보호된 cgroup을 후보에서 제외 | 완료 (종료 제외는 VM에서 확인. `MemoryLow`는 이 시나리오에서 효과가 없어 선택 설정으로 둠) |

M3-7(리플레이 테스트)은 M2 삭제로 폐기했다. 완료한 부분은 WSL에서 단위 테스트와 스레드 경쟁 검사를 통과했고, 데몬은 WSL에서 dry-run으로 기동·신호 종료를 확인했다(root, 프로세스 종료는 시험하지 않음). 실제 종료와 해소는 VM에서 확인한다.

VM 검증(2026-11-13, 원본 `results/m3/20261113/`): 서비스 기동, 컨테이너 cgroup 이름, 실제 종료와 해소(`full_pct=10`에서 단일 hog 3/3, 대조군 3/3), 보호된 cgroup 제외(유효 2/2)를 확인했다. 데몬 종료 없이 커널 OOM killer가 먼저 종료한 경우가 9회 중 1회 있었다. 데몬을 끈 대조군, 정상 버스트의 오탐은 M4에서 본다. `MemoryLow`는 효과가 없었다(선택 설정으로 격하). 디스크를 처리량 약 10.9 MB/s로 제한한 조건(길벗 장애의 병목, 다른 세션 전달)에서 데몬 dry-run(꺼짐과 같음)은 3/3 livelock이 5분 넘게 이어졌고(OOM killer 개입 없음), 실제 종료 모드는 3/3 가용 메모리가 바닥난 뒤 14~22초에 종료해 정지가 13~21초로 줄었다. 다만 memory full만 보는 규칙은 굳어진 livelock에서 늦게 충족되는 경우가 있어(기록 재생 기준 67초, 147초) io 경로를 추가했다(M3-11, 재생에서 19~24초).

완료 조건: VM에서 dry-run 판단 로그가 남고, dry-run을 끄면 실제 종료 후 해소된다. 유휴 시 `VmRSS`·`VmLck`와 스트레스 중 루프 지연을 기록한다.

## M4. 효과 검증

필수 프로세스 E와 부하 하나(`RUNAWAY_GROWTH`, `SPIKE_MEM`, `BURST_MEM`, 정상 버스트)를 함께 두고 데몬 dry-run(꺼짐 대용)과 켜짐을 3회씩 비교한다(Facebook oomd 글의 합성 테스트를 줄인 방식, 그래프도 같은 모양). 합격은 결과로 판단하고,
누가 종료됐는지는 기록 지표다. 자세한 내용은 [validation/overview.md](validation/overview.md). 완료 조건은 보고서 `docs/reports/M4-validation.md`에 V1~V5가 실측과 추론을 구분해 판정되고, 임계값 재보정 후보와 후속 개선 항목이 정리되는 것이다. 기준 디스크 조건은 처리량 약 10.9 MB/s 제한이다. 한 실행은 T0 이후 최대 5분이고, 모두 21회(부하 3종 × 2조건 × 3회 + 정상 버스트 dry-run 3회)다. `memory.min` 소량 선택 시험과 데몬 `mlock` 대조군(이슈 #6)은 M4 밖의 선택 시험으로 둔다.

## 후속 (M5, M7)

- **개선 기능(M5)**: 대상 구역 `full`을 함께 보는 복합 판단, 단계적 대응(`memory.high` 감속, SIGTERM 후 SIGKILL), 종료 직전 스냅샷, 종료 후 `process_mrelease`, oomd식 3계층 선택과 prefer/avoid 우선순위
- **확장(M7)**: 기존 도구와의 비교(systemd-oomd, earlyoom, MGLRU `min_ttl_ms`), swap이 있는 환경, 메모리 크기·커널 버전·실행 형태 조합, 실제 클라우드 인스턴스(t3.micro) 측정(AWS 리소스 생성 전 별도 확인), eBPF·커널 패치 같은 심화 연구

## 미결 사항

- 컨테이너 런타임별 실제 cgroup 이름(기본 `target_match`는 임시)
- PSI 트리거 등록 실패 시 동작(제안: 시작 거부)
- `SPIKE_MEM` 즉시 할당의 스래싱 여부와 `BURST_MEM`·정상 버스트의 크기(예비 실행으로 결정, 시도 횟수 상한은 제안 단계)
- 공개 시점의 라이선스(oomd가 GPL-2.0이므로 코드는 가져오지 않는다)

## 작업 규칙

- 코드 주석·커밋 메시지·문서는 한국어, 식별자는 영어.
- 할당 금지 구간은 함수 위에 `/* 핵심 경로: 할당 금지 */`로 표시한다.
- 실측과 추론을 구분하고, 측정하지 않은 수치는 문서에 쓰지 않는다.
- 작업 ID(예: M3-2)는 커밋 메시지에 적어 추적한다. 설계가 바뀌면 해당 설계 문서에 짧게 남긴다.
